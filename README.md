# SalesIQ — Mini AI Business Intelligence Assistant

A compact natural-language sales analytics app built with Python, Flask, SQLite, Pandas, HTML/CSS and Chart.js.

## Features

- Natural-language question box with suggested prompts.
- Supports total revenue, highest-revenue product, monthly revenue trend, highest-sales region and month-to-month revenue comparison.
- Every answer is backed by a predefined, deterministic SQL query and returns supporting figures.
- CSV import with column matching, type validation and removal of invalid rows.
- Dashboard KPIs and a monthly revenue chart.
- Automated API and CSV validation tests.
- Read-only database connection for analytics; no arbitrary SQL from users is executed.

## Requirements

- Python 3.11+ recommended
- pip
- Internet access is optional for the dashboard chart and Google Fonts (the app and API run locally without those assets).

## Run on Windows (PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:5000.

If PowerShell blocks virtual-environment activation, use Command Prompt or call `.venv\Scripts\python.exe -m pip install -r requirements.txt` and `.venv\Scripts\python.exe app.py`.

## Load the supplied company CSV

1. Open the dashboard.
2. Under **Use your own sales data**, select the provided `.csv`.
3. Click **Import CSV**.
4. The app supports the company's columns (`Order_date`, `Product`, `Region`, `Quantity`, `Unit_price`, `Discount_amount`, `Status`) and simpler CSVs with date, product, region, and revenue/sales. Revenue for quantity-based datasets is calculated as quantity × unit price − discount. Returned/cancelled records and invalid rows are excluded.
5. Import replaces the current dataset. The app reports how many records were loaded and how many invalid rows were removed.

The company-provided `sales_data.csv` is included and imported automatically on first launch. For this dataset, revenue is calculated as `Quantity × Unit_price − Discount_amount`; only completed transactions with valid dates, products, regions, positive quantities and valid prices are included. Returned rows and invalid rows are excluded. The import screen supports this dataset's columns as well as simpler CSVs with a revenue/sales column.

## Example questions

- What is the total revenue?
- Which product generated the highest revenue?
- What is the monthly revenue trend?
- Which region generated the highest sales?
- How did revenue change between 2025-01 and 2025-02?

For month comparisons, use `YYYY-MM` values or month names with a year. If a month has no transactions, its revenue is treated as zero. Percentage change is reported as unavailable if the first month's revenue is zero.

## API

### `POST /api/ask`

Request:
```json
{"question":"What is the total revenue?"}
```

Successful response includes `answer`, `intent`, `evidence`, `chart`, and `sql_label`. Unsupported questions and invalid request bodies return HTTP 400 with an `error` field.

### `GET /api/summary`

Returns KPI totals and monthly revenue series.

### `POST /api/upload`

Multipart form field `file` accepts a CSV file. Upload is limited to 10 MB.

```text

           |
           | JSON / multipart HTTP
           v
Flask API (/api/ask, /api/summary, /api/upload)
           |
           +--> Question intent parser (allowlisted intents)
           |          |
           |          v
           |     Fixed parameterized SQL
           |
           +--> Pandas CSV validation/cleaning
                      |
                      v
                 SQLite sales table
```

## AI-assisted interpretation and reliability

This version uses a lightweight, AI-assisted-style natural-language intent parser rather than calling an external LLM. It maps common question phrases to a small set of supported analytical intents. The results themselves are calculated by fixed SQL queries, not generated by a language model.

Safety and reliability choices:
- No user-provided SQL is executed.
- Analytics use a SQLite read-only connection.
- Queries are predefined and parameters are bound separately.
- Unsupported questions return a clear error instead of a guessed answer.
- CSV rows with invalid dates, missing product/region/revenue, non-numeric revenue, or negative revenue are discarded and counted.
- Database errors are handled without returning internal stack traces to users.
- Upload replaces the existing dataset, so confirm the correct CSV before importing.

## Known limitations

- Intent matching is rule-based and supports only the documented question types and common phrasings.
- Month comparisons work best with `YYYY-MM` or month names and a year.
- Revenue assumes the CSV's selected `Sales`/`Revenue` column is already the transaction total; quantity × unit price is not inferred automatically.
- All revenue is shown in a single currency format. The app does not infer currency from the source.
- The chart uses Chart.js from a CDN; if offline, the chart may not render, but API answers still work.
- This is a local demonstration, not a production service: authentication, role-based access, upload history, backups, and multi-user isolation are not included.
